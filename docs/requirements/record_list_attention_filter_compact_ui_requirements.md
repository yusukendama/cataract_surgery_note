## 0. 本書の位置付け

本書は、症例一覧画面にある「要対応のみ」フィルターの機能、名称および既存動作を維持したまま、補助的な表示切り替えとしてコンパクトかつ穏やかに見せるためのUI要件を定義する。

「要対応」はレビュー状態だけでなく、動画未登録、動画ファイルの欠損、不正な動画参照、動画状態の確認失敗も含む。したがって、本改訂では「レビュー未完了」への名称変更およびレビュー状態だけに絞る仕様変更を行わない。

本書における「必須」は受け入れに必要な要件を示す。「推奨」は、採用しない場合に理由を実装記録へ残す品質要件を示す。

---

## 1. 目的

症例一覧上部の「要対応のみ」フィルターが主要操作のように強く見える状態を改善し、次を実現する。

1. 「要対応のみ」が一覧を絞り込む補助操作であることを視覚的に伝える
2. 総手術件数、新規症例、症例カード等の主要情報・操作より視覚的優先度を下げる
3. 選択状態、操作領域、読み上げおよび文字拡大時の可読性を損なわない
4. 現行の抽出条件、状態取得、月表示、空表示および状態保持を変更しない

今回の変更は機能再設計ではなく、既存の単一選択式`FilterChip`の視覚調整である。

---

## 2. 基本方針

### 2.1 名称と意味を維持する

表示文言は引き続き次のとおりとする。

> 要対応のみ

レビュー状態と動画状態の双方を対象にするため、「レビュー未完了」「未レビューのみ」等へ変更しない。

### 2.2 単一トグルを維持する

現行と同じ1個の`FilterChip`を使用し、次の2状態を切り替える。

| チップの状態 | 一覧の表示状態 |
| --- | --- |
| OFF（未選択） | 通常一覧に含まれる全症例を表示 |
| ON（選択中） | 要対応症例のみを表示 |

「すべて」と「要対応」の2択セグメントには変更しない。

### 2.3 視覚的優先度だけを下げる

フィルターは、総手術件数と同じ上部集計領域内に置く。画面幅いっぱいのボタンや独立した主要アクションとして扱わず、内容幅に応じた小型の補助コントロールとして表示する。

### 2.4 機能回帰を許容しない

抽出条件、判定中・失敗時の扱い、空表示、月の展開状態、総手術件数、選択状態およびデータ構造は変更しない。UI調整のために判定ロジックを複製または再実装しない。

## 4. 維持する機能仕様

### 4.1 要対応症例の定義

現行の「要対応のみ」をONにした際と同一の判定結果を用いる。症例は、次のいずれかが確定した場合に要対応とする。

#### レビューに関する要対応

- `reviewSchemaVersion`が現行レビュー方式の対象で、レビュー状態が「未レビュー」である
- `reviewSchemaVersion`が現行レビュー方式の対象で、レビュー状態が「レビュー中」である

レビュー完了は、レビューだけを理由とする要対応には含めない。`reviewSchemaVersion`が未設定の既存症例はレビュー状態を推測せず、レビューだけを理由に要対応へ含めない。

#### 動画に関する要対応

- 動画が関連付けられていない
- 関連付け済みの動画ファイルが見つからない
- 動画参照が不正である
- 動画状態の確認に失敗している
- 動画状態Providerがエラーを返している

レビュー完了症例および旧スキーマ症例であっても、動画に関する要対応があれば表示対象とする。レビューまたは動画の一方で要対応が確定していれば、他方が判定中でも対象症例を表示する。

レビュー完了かつ動画正常の症例は表示対象外とする。

### 4.2 OFF時の動作

- 通常一覧に含まれる全症例を表示する
- 要対応判定のためだけに全症例の動画状態を追加取得しない
- 症例の並び順、月分類およびカード表示は現行どおりとする

### 4.3 ON時の動作

- 要対応と確定した症例のみを即時に表示する
- 確認ダイアログや追加操作を要求しない
- フィルター操作によって症例データを変更しない
- 表示対象内の並び順を変更しない
- 要対応と確定済みの症例がある場合は、他症例の判定完了を待たずに表示する

### 4.4 判定中・取得失敗・空表示

既存の表示条件と文言を維持する。

| 状態 | 表示 |
| --- | --- |
| 要対応症例がなく、一部の要対応判定が進行中 | `要対応の症例を確認しています…`を表示し、空表示を確定しない |
| 要対応症例を表示中で、残りの判定が進行中 | 判定済みの症例に加えて`要対応の症例を確認しています…`を表示する |
| 工程情報等の取得に失敗し、要対応症例がないと確定できない | 既存の取得失敗表示と再読み込み導線を表示し、`要対応の症例はありません`を表示しない |
| 全対象の判定が完了し、要対応症例が0件 | `要対応の症例はありません`を表示する |
| 動画状態の確認に失敗 | 当該症例を要対応として表示し、症例カード上の既存の再試行導線を提供する |

UI変更によって、次の既存文言を変更しない。

- `要対応の症例を確認しています…`
- `要対応状態を確認できませんでした。再読み込みしてください。`
- `要対応の症例はありません`

一覧全体が0件の場合は、フィルターを表示せず、既存の「まだ症例がありません」を含む空表示を維持する。

### 4.5 総手術件数

- 総手術件数は、フィルター適用前の通常一覧に含まれる全症例数とする
- フィルターのON・OFFだけでは件数を変化させない
- 症例の追加、削除または正常なデータ再読み込みで全症例数自体が変化した場合は更新する
- フィルター結果の件数をチップ内または件数バッジとして追加表示しない

例：全症例100件、要対応症例4件の場合、フィルターON時も「総手術件数 100件」と表示する。

### 4.6 月ごとの表示と展開状態

- フィルターON時は、表示対象症例が1件以上ある月だけを表示する
- 月見出しの件数は、その時点で実際に表示される症例数とする
- フィルターON時に表示対象となる月のうち、すでに展開中の月があればその状態を維持する
- 表示対象となる月が1つも展開されていない場合は、表示対象症例がある最新月を展開する
- フィルターで一時的に非表示となった月の展開状態を破棄せず、OFFへ戻したときに復元する
- 月の並び順、月内の症例順および複数月を同時に展開できる仕様を維持する
- 新しい最新月の追加、症例がなくなった月の除外等、データ更新時の既存同期動作を維持する

### 4.7 フィルター選択状態

- 初期状態はOFFとする
- 症例一覧画面がNavigation Stack上に同一インスタンスとして残っている間は選択状態を保持する
- 症例詳細・レビュー画面との往復、一時的な再ビルド、画面回転、リサイズおよび一時的な一覧再取得失敗では状態を初期化しない
- アプリ終了後まで永続化しない
- フィルター状態のためにデータベースや設定ストレージを追加しない
- 症例一覧画面が破棄され、新しく生成された場合はOFFから開始する

### 4.8 スクロール動作

本変更を理由に、フィルター操作時または詳細画面から戻った時のスクロール制御を追加・変更しない。選択状態の変更による通常の一覧再構成と、表示範囲内への既存の補正を除き、明示的に先頭へ移動させない。

## 5. UI要件

### 5.1 表示形式

フィルターは、現行どおり総手術件数カード内の単一`FilterChip`として表示する。

広い画面の基本配置：

```text
［総手術件数 100件］                 ［要対応のみ］
```

狭い画面または文字拡大時：

```text
［総手術件数 100件］
［要対応のみ］
```

### 5.2 コンパクトさ

通常の文字サイズでは次を満たす。

- チップの横幅はラベルと必要な選択表現に応じた内容幅とし、画面幅いっぱいへ引き伸ばさない
- 視覚上のチップ本体は既存の主要ボタンより低い高さとし、32〜36 logical pixels程度を目安とする
- 内部余白と要素間隔は、ラベルの読みやすさを保てる範囲で現行よりコンパクトにする
- ラベルには既存テーマの補助操作向け文字スタイルを使用し、総手術件数より強い文字サイズ・ウェイトにしない
- elevationや影による強調を追加しない

視覚上のサイズを縮小しても、実際の操作領域およびSemantics領域は44 × 44 logical pixels以上を確保する。

### 5.3 未選択状態

- 背景は透明または中立的なsurface系カラーとする
- 境界を認識できる細い枠線を使用する
- 文字色は可読性を満たす`onSurfaceVariant`等のテーマ色を用いる
- 警告色、エラー色、影または通知バッジで強調しない

### 5.4 選択状態

- 淡いテーマカラーまたは中立的な選択背景を使用する
- チェックマーク、背景、枠線または文字ウェイトを組み合わせ、色だけに依存せず選択状態を示す
- 未選択状態との差は明確にする一方、主要ボタンやエラー表示より強く見せない
- 強い赤色、強いオレンジ色、エラー色、警告三角形、感嘆符、通知ドットを使用しない

本節の穏やかな配色要件は上部フィルターにのみ適用する。症例カード内の既存ステータス、取得失敗表示および再試行導線の意味色は変更しない。

### 5.5 件数・アイコン

- `要対応のみ 3`、`要対応のみ（3件）`等の件数を表示しない
- 件数バッジや通知ドットを追加しない
- 選択を示すチェックマーク以外の警告・タスク系アイコンを追加しない
- ラベル「要対応のみ」を途中で省略またはフェードさせない

### 5.6 操作

- 未選択のチップを操作するとONになる
- 選択中のチップを操作するとOFFになる
- 切り替え結果は即時に一覧へ反映する
- 無効状態は新設しない
- 押下、フォーカス、ホバー等、プラットフォームが提供する状態フィードバックを判別できること

## 6. アクセシビリティ要件

### 6.1 Semantics

フィルターは、支援技術から1個の操作可能なコントロールとして認識できること。表示用の子要素による重複読み上げを発生させない。

次を認識できるSemanticsを提供する。

- ラベル：`要対応のみ`
- 操作可能であること
- 選択中または未選択であること
- タップによって状態を切り替えられること

状態変更後はSemanticsの選択状態も同時に更新する。VoiceOverおよびTalkBackの読み上げ順で、総手術件数の後にフィルターへ自然に移動できること。

### 6.2 操作領域

- 操作領域とSemantics領域はいずれも44 × 44 logical pixels以上とする
- 視覚上のチップ外に透明な余白を使う場合も、隣接操作と重ならないこと
- タップ、キーボードまたは支援技術による操作で同じ状態遷移になること

### 6.3 文字拡大と可読性

- Dynamic TypeおよびFlutterの文字拡大へ対応する
- 少なくとも320 logical pixels幅・文字倍率2.0で、ラベルを省略記号またはフェードにより欠落させない
- ラベル、チェックマークおよび総手術件数が重ならない
- 必要に応じてチップの高さ拡張または次行への折り返しを許容する
- 優先順位は、文言の欠落防止、44 × 44以上の操作領域、要素の非重複、コンパクトさの順とする

### 6.4 色とモーション

- Light ModeとDark Modeの双方で文字および境界のコントラストを確保する
- ラベルと背景のコントラスト比は4.5:1以上とする
- 高コントラスト設定時は、チップの境界と背景のコントラスト比を3:1以上とする
- 高コントラスト設定および色覚特性にかかわらず選択状態を判別できること
- 新しい装飾アニメーションを必須にしない
- アニメーションを使用する場合は既存のReduced Motion対応に従い、無効でも状態を理解できること

## 7. レスポンシブ要件

次の環境で、overflow、クリッピング、要素の重なり、操作不能または不自然な全幅化が発生しないこと。

- iPhone縦表示・横表示
- iPad縦表示・横表示
- iPad Split View
- Androidの小幅画面
- 画面リサイズ
- 320 logical pixels程度の利用可能幅
- 通常および大きな文字倍率
- Light Mode・Dark Mode

横方向に総手術件数とチップを収められない場合は、既存の`Wrap`相当の配置によりチップを次の行へ送る。折り返し時も左端の標準コンテンツ余白へ揃え、ラベルを切らない。十分な横幅がある場合は、総手術件数を左、フィルターを右に配置する。

## 8. データ・性能・後方互換性

- データベースマイグレーションを追加しない
- 症例データの保存形式を変更しない
- 既存症例のレビュー状態または動画参照を変更しない
- 要対応判定用のgetter、Provider、predicate等が存在する場合は既存経路を再利用する
- UI調整のために動画ファイルアクセス、プレイヤー初期化または追加の逐次待機を発生させない
- OFF時の不要な動画状態監視を新設しない
- 折りたたまれた月の症例カードに関する既存の遅延構築特性を損なわない
- 旧スキーマ症例の要対応判定を変更しない

## 9. テスト要件

### 9.1 既存機能の回帰テスト

以下を自動テストで確認する。既存テストが同じ事項を十分に検証している場合は、そのテストを維持してよい。

1. 初期状態でフィルターがOFFであり、全症例を表示する
2. ONで未レビューおよびレビュー中の症例を表示する
3. ONで動画未登録、動画欠損、不正参照および動画状態確認失敗の症例を表示する
4. レビュー完了かつ動画正常の症例を除外する
5. 旧スキーマ症例はレビュー状態だけでは対象にせず、動画問題がある場合は対象にする
6. レビューまたは動画の一方で要対応が確定していれば、他方の判定中でも症例を表示する
7. 判定中は空表示を確定しない
8. 判定失敗時は失敗表示と再読み込み導線を示し、正常な空表示を出さない
9. 動画状態の確認失敗を要対応として表示し、既存の再試行で復旧できる
10. 要対応が0件と確定した場合だけ`要対応の症例はありません`を表示する
11. フィルター操作で症例データおよび全体の並び順を変更しない
12. ON・OFFで総手術件数を変更しない

### 9.2 月・状態保持・スクロールの回帰テスト

1. ON時に対象がない月の見出しを表示しない
2. 月見出しの件数が現在表示中の件数になる
3. ON時に既存の展開月を維持し、対象月がすべて閉じている場合だけ最新対象月を展開する
4. OFFへ戻した際に、フィルターで隠れていた月の展開状態を復元する
5. 詳細画面との往復、再ビルドおよび一時的な一覧取得失敗で選択状態と月展開状態を保持する
6. 新しい画面インスタンスではフィルターがOFFになる
7. UI変更によって新しい強制スクロールを発生させない

### 9.3 UI・アクセシビリティテスト

1. 表示文言が`要対応のみ`のままである
2. `すべて`または`レビュー未完了`のセグメントを追加していない
3. チップが内容幅で表示され、通常幅で全幅化しない
4. 選択時と未選択時の視覚状態が異なり、チェック等により色以外でも判別できる
5. フィルターに要対応件数、警告アイコンまたは通知バッジがない
6. 操作領域とSemantics領域が44 × 44 logical pixels以上である
7. Semanticsのラベル、操作可能性および選択状態がON・OFFに追従する
8. 320 logical pixels程度の幅および文字倍率2.0で、省略記号やフェードによるラベル欠落、重なりまたはoverflowがない
9. 狭幅時に総手術件数とフィルターが安全に折り返す
10. Light Mode、Dark Modeおよび高コントラスト設定で可読性と選択状態を確認できる

### 9.4 実行確認

- 新仕様と無関係な既存テストがすべて成功すること
- 旧フィルターの機能仕様を検証する既存テストを維持し、UI構造に依存する部分だけを承認済みの表示仕様に合わせて更新すること
- `flutter analyze`が成功すること
- `flutter test`が成功すること
- iPhone、iPad Split Viewおよび小幅画面相当で目視またはGoldenテストによる表示確認を行うこと
- VoiceOverまたはTalkBackで実機・シミュレータ確認を行うこと

## 10. 受け入れ基準

以下をすべて満たした場合、本変更を受け入れ可能とする。

- 「要対応のみ」の名称が維持されている
