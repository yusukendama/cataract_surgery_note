# 保護ストレージ起動復旧 ホットフィックス要件

## 1. 背景

TestFlight Build 19で、端末のロック解除後も「保護されたデータを利用できません」と表示され、既存の症例、レビュー、動画へ進めない事象を確認した。

Build 19の起動処理は、症例DBだけでなく管理動画ツリー全体の保護属性と構造をDBオープン前に検証している。このため、動画領域の一部に保護属性不一致または想定外エントリがあるだけで、保護済みの症例DBとレビューも利用不能になる。

## 2. 目的

- 症例DBの保護を維持したまま、動画領域の局所的な問題をアプリ全体の起動失敗から分離する。
- 既存の症例・レビューを削除または再作成せずに読み込めるようにする。
- 実機固有の保護属性失敗を、パスや患者情報を含まない診断コードで識別可能にする。

## 3. 必須要件

### 3.1 起動境界

- 起動時の必須検証対象は、protected data availabilityとDBファイル群に限定する。
- DB本体および存在するSQLite sidecar（WAL、SHM、journal）は、`NSFileProtectionComplete`の適用と読戻しに成功しなければDBを利用可能にしない。
- SQLiteがDBオープン後に生成したsidecarで属性不一致を検出した場合、内容を変更せず保護属性を修復し、再度読戻す。
- DBファイル群の保護を確認できない場合は、従来どおりfail closedとする。

### 3.2 動画障害の分離

- 管理動画ツリー全体の走査をDBオープンの前提条件にしない。
- 管理動画は、既存のメンテナンス処理および個別アクセス時に保護属性と安全なパスを検証する。
- 動画の保護失敗、バックアップ除外失敗、想定外エントリは、その動画または動画メンテナンスを失敗させるが、症例一覧、症例詳細、レビュー記録の読込みを遮断しない。
- 検証不能な動画を推測で再生、移動、削除しない。

### 3.3 標準ディレクトリ

- Documentsディレクトリには`NSFileProtectionComplete`を適用する。
- OSによる標準ディレクトリ属性の読戻し差異だけではDBを遮断しない。
- この例外はディレクトリ自体に限り、DB本体とsidecarの厳格な読戻しを省略してはならない。

### 3.4 診断コード

保護失敗画面には、次のような非機密コードを表示する。

- `PS-DB-DIR`: DBディレクトリの構造または作成失敗
- `PS-DB-FILE`: DB本体の保護失敗
- `PS-DB-SIDECAR`: WAL、SHM、journalの保護失敗
- `PS-VIDEO-DIR`: 管理動画ディレクトリの保護失敗
- `PS-VIDEO-FILE`: 管理動画ファイルの保護失敗
- `PS-CHANNEL`: ネイティブ連携失敗
- `PS-DB-OPEN`: DBオープンまたはマイグレーション失敗
- `PS-UNKNOWN`: 分類不能

診断情報にsandbox path、ファイル名、症例ID、動画名、ネイティブ例外本文を含めない。

## 4. データ保全

- 起動復旧処理でDB、症例、レビュー、動画を削除しない。
- 既存DBの保存場所とスキーマを変更しない。
- 動画参照、工程位置、自己評価、反省点、症例メモを変更しない。
- 動画メンテナンスが失敗した場合はfail closedとし、自動削除を進めない。

## 5. リリース

- リリースバージョンとビルド番号は`1.0.0+21`とする。
- Build 18からの上書き更新と、Build 19からの上書き更新を実機で確認する。
- 更新後に既存の症例一覧、症例詳細、工程レビューが読み込めることを確認する。
- 管理動画が再生できること、または動画だけの検証失敗として隔離されることを確認する。
- 端末ロック中は従来どおり保護データを開かず、解除後の明示的な再試行で復帰することを確認する。
- `flutter analyze`、全Flutterテスト、iOS unit test、署名なしReleaseビルドを成功させる。

## 6. 受け入れ条件

- [ ] 動画ツリーに想定外エントリがあっても、保護済みDBの起動を妨げない。
- [ ] DB本体またはsidecarの保護を確認できない場合は起動を遮断する。
- [ ] sidecarの弱い保護属性を修復してからDBの結果を返す。
- [ ] 保護失敗画面に非機密な診断コードが表示される。
- [ ] 既存データの削除・初期化・移動を行わない。
- [ ] Build 21としてArchiveできる。
