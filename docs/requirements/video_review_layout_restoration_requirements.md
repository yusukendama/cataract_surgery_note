## 0. 本書の位置付け

本書は、`docs/requirements/design_ux_update_requirements.md` のうち、工程レビュー画面の動画表示と操作レイアウトに関する補足要件である。

## 1. 目的

工程レビュー画面において、通常の縦画面ではスクロールせずに動画プレイヤー全体へアクセスでき、動画を見ながら次の操作を繰り返せる状態を復旧する。

1. 手術動画の内容を確認する
2. 再生／一時停止する
3. 5秒または15秒単位で前後移動する
4. シークバーで再生位置を変更する
5. 工程の開始・終了位置を決定する

今回の改修では、動画を画面幅いっぱいに大きく表示することよりも、動画、シーク、再生操作へ直ちにアクセスできることを優先する。

> 動画を最大化することよりも、動画を見ながら再生操作と工程記録を繰り返せることを優先する。

---

## 2. 現在の問題と直接原因

現行画面は、AppBar下の画面本体を次のように構成している。

```text
Column
├─ 高さを画面の約42%に制限した上部領域
│  └─ SingleChildScrollView
│     └─ 動画、時刻・速度、シークバー、5つの再生操作ボタン
├─ 工程タブ
└─ 工程レビュー内容
```

上部領域の高さは最大360 logical pixelsに制限される一方、その内部では動画が先に画面幅を基準として大きく表示される。このため、小さい縦画面では、時刻・速度、シークバー、再生操作ボタンが上部領域の下へ押し出される。

結果として、ユーザーは次の往復操作を強いられる。

1. 動画を見る
2. 上部領域を縦スクロールする
3. 再生またはスキップボタンを押す
4. 動画が見える位置へ戻る

これは「動画を見ながら工程境界を探す」という主要機能を妨げる不具合である。

## 3. 用語と適用状態

### 3.1 動画プレイヤー領域

本書の「動画プレイヤー領域」は、次の全要素を含む一体の領域を指す。

1. 動画表示面
2. 現在位置／総時間の表示
3. 再生速度の表示・変更操作
4. シークバー
5. 15秒戻る、5秒戻る、再生／一時停止、5秒進む、15秒進むの5操作

「動画と5つのボタンだけ」を指すものではない。

### 3.2 工程レビュー領域

本書の「工程レビュー領域」は、次を含む。

- 工程選択用TabBar
- 選択中の工程の開始・終了設定
- 記録済み時刻と所要時間
- 再設定
- 自己評価・反省点
- 症例メモ
- その他の既存レビュー操作

### 3.3 通常状態

本書の「通常状態」は、次をすべて満たす状態とする。

- 利用可能な動画が症例へ登録されている
- `VideoPlayerController` の初期化が正常に完了している
- 動画再生エラーが発生していない
- ソフトウェアキーボードが表示されていない
- 縦画面である

「画面を開いた直後」という表現は、非同期初期化中を含めず、「利用可能な動画の初期化完了後」と解釈する。

### 3.4 通常状態以外

次の状態では、動画プレイヤー全体の常時表示を必須としない。

- 初回データ読み込み中
- 動画確認中または動画初期化中
- 動画未登録
- 動画実体なし
- 不正な動画参照
- 動画確認失敗または再生失敗
- 症例削除済み
- キーボード表示中
- 高さが厳しく制限された横画面またはウインドウ状態

ただし、各状態で既存の説明、データ保護、回復操作、操作到達性を維持し、overflowやクラッシュを発生させてはならない。

## 4. 最優先のUX要件

通常状態の縦画面では、ユーザーが縦スクロールしなくても、動画プレイヤー領域の全要素が同時に完全表示されていること。

次は不可とする。

- 一部だけ見えている
- 画面端、Safe Area、AppBar、Home Indicatorで切れている
- プレイヤー領域内を少しスクロールすれば見える
- 動画を見る位置と再生ボタンを押す位置が異なる
- 時刻・速度表示またはシークバーだけが隠れている
- 5つの再生操作ボタンの一部だけが隠れている

工程レビュー領域を縦スクロールしても、動画プレイヤー領域の位置と表示は変化しないこと。

---

## 5. 基本レイアウト

通常状態では、画面本体を次の2領域へ分ける。

```text
Scaffold
├─ AppBar
└─ SafeAreaを考慮した画面本体
   └─ Column
      ├─ 動画プレイヤー領域（縦スクロール不可）
      │  ├─ 動画
      │  ├─ 現在位置・総時間／再生速度
      │  ├─ シークバー
      │  └─ 5つの再生操作ボタン
      ├─ 工程選択TabBar
      └─ Expanded
         └─ 選択中タブの工程レビュー内容（縦スクロール可）
```

### 5.1 動画プレイヤー領域

- 動画から5つの再生操作ボタンまでを、単一の縦スクロール不可領域として扱う
- 動画と再生操作ボタンの間に、工程記録UI、通知バナー、大きな余白を挟まない
- 動画プレイヤー領域自体を `SingleChildScrollView`、`ListView` 等へ入れない
- 通常状態では、プレイヤー領域の一部を折りたたんだり、メニューへ格納したりしない

### 5.2 工程レビュー領域

- TabBarは動画プレイヤー領域の直下へ置く
- TabBarの既存の横スクロールは維持してよい
- 縦スクロールは、選択中タブの内容だけに持たせる
- 非選択タブのスクロール状態やドラフトを不必要に初期化しない
- タブ切り替えによって動画プレイヤーを再生成しない

### 5.3 工程レビュー領域の最低表示量

通常状態では、動画プレイヤー領域を優先することで工程レビュー内容の表示領域をゼロにしてはならない。

- TabBar全体を表示する
- TabBarを除く、選択中タブ内容の表示領域を96 logical pixels以上確保する
- 96 logical pixelsを確保できない場合は、余白、動画高さの順に縮小する
- 工程レビュー内容をスクロールして、開始・終了・再設定・メモ等の既存操作へ到達できること

## 6. 高さの決定方法

### 6.1 利用可能高さ

動画サイズは画面幅だけで決定しない。`LayoutBuilder` 等から得られる、AppBarと実際のSafe Areaを反映した画面本体の制約を基準にする。

Flutterの親Widgetですでに除外済みのAppBar、Safe Area、`viewInsets`を重複して差し引いてはならない。

概念上、通常状態の高さ配分は次のとおりとする。

```text
画面本体の利用可能高さ
  = 動画プレイヤー領域
  + 工程TabBar
  + 工程レビュー内容の表示領域（96px以上）
```

動画に使用できる最大高さは、次の考え方で求める。

```text
動画の最大高さ
  = 画面本体の利用可能高さ
  - 工程TabBarの実際の高さ
  - 工程レビュー内容の最低表示高さ
  - 時刻・速度行の実際の高さ
  - シークバーの実際の高さ
  - 5つの再生操作ボタンの実際の高さ
  - プレイヤー内の必要最小限の余白
```

固定端末名や特定画面だけに合わせた動画の固定高さを、成立条件としてはならない。

### 6.2 高さ不足時の調整順

通常状態で高さが不足する場合は、次の順で調整する。

1. 不要な上下余白を減らす
2. プレイヤー内部の必要最小限の間隔へ調整する
3. 動画を元のアスペクト比のまま縮小する
4. 工程レビュー内容を、その最低表示高さを残して縦スクロールさせる

次は行わない。

- 動画プレイヤー領域を縦スクロールさせる
- 再生操作ボタンを画面外へ押し出す
- 5つの再生操作の一部を非表示にする
- 5つの再生操作をメニュー内へ格納する
- 5つの再生操作を2段へ折り返す
- 工程レビュー内容の表示領域をゼロにする
- 動画をクロップして高さを確保する

---

## 7. 動画の表示仕様

- 動画はメタデータで得られる元のアスペクト比を維持する
- 縦横いずれの動画でも、表示領域内へ `BoxFit.contain` 相当で全体を収める
- 余白が生じることは許容する
- 縦方向の余裕がない場合は、動画全体を縮小する
- 動画を不自然に縦横へ引き伸ばさない
- 動画の一部を意図せずクロップしない
- 再生操作ボタン、時刻、シークバーを動画へ重ねて術野を隠さない
- 不正または0以下のアスペクト比を通常状態として扱わず、既存の再生エラー状態へ遷移させる

少なくとも16:9、4:3、9:16相当のアスペクト比で、全体表示とoverflowなしを確認する。

## 8. 再生操作ボタン

既存の5操作と配置順を維持する。

| 配置順 | 操作 |
|---:|---|
| 1 | 15秒戻る |
| 2 | 5秒戻る |
| 3 | 再生／一時停止 |
| 4 | 5秒進む |
| 5 | 15秒進む |

```text
［15秒戻る］［5秒戻る］［再生／一時停止］［5秒進む］［15秒進む］
```

### 8.1 表示条件

- 5つすべてを1行で表示する
- 2段に折り返さない
- 横スクロールを必要としない
- 中央へ再生／一時停止ボタンを置く
- 横幅不足時は、不要な左右余白、ボタン間隔、テキストの簡略化、アイコン中心表示の順で調整する
- テキストを省略しても、TooltipとSemanticsでは方向と秒数を識別できること

### 8.2 タップ領域とアクセシビリティ

- 各操作のタップ可能なSemantics領域は44×44 logical pixels以上とする
- Materialボタンでは48×48 logical pixels以上を推奨する
- 中央の再生／一時停止操作は48×48 logical pixels以上とする
- 隣接する操作のSemantics領域を重ねない
- 視覚順とVoiceOverフォーカス順を一致させる
- 再生状態に応じて、アイコン、Tooltip、Semanticsを「再生」「一時停止」で切り替える
- 無効状態では、その理由をTooltipまたはSemanticsで理解できるようにする

---

## 9. 再生機能の維持

今回の改修はレイアウト修正を中心とし、既存の動画制御ロジックを原則として変更しない。

次を維持する。

- 動画再生
- 一時停止
- 5秒戻る／進む
- 15秒戻る／進む
- 動画先頭より前へ移動しない制御
- 動画末尾より後へ移動しない制御
- 現在位置／総時間表示
- シーク操作
- 再生速度変更
- 再生状態に応じたアイコン変更
- タブ切り替えや同一動画のProvider更新でControllerを再生成しないこと
- 再生位置通知で画面全体や工程フォームを再ビルドしないこと

既存の `VideoTransportControls`、`VideoSeekCoordinator`、`_seekRelative()` 相当の処理を重複実装しない。

---

## 10. 工程レビュー操作

- 工程選択、開始、終了、所要時間、再設定、自己評価、反省点、症例メモ、保存の既存機能を維持する
- 開始・終了時刻の即時保存と、評価・反省点・症例メモの明示保存という既存契約を変更しない
- 工程レビュー内容を縦スクロールして開始・終了操作を画面内へ表示しても、動画プレイヤー領域は動かない
- 開始・終了操作をタップする時点で、通常状態の動画と5つの再生操作が引き続き画面内に存在する
- 工程レビューの表示順、工程定義、保存済み状態を不必要に変更しない

## 11. 小さい画面、文字倍率、画面方向

### 11.1 通常縦画面の必須確認

少なくとも次のlogical viewportで確認する。

| 区分 | Viewport | 文字倍率 | 必須結果 |
|---|---:|---:|---|
| 最小phone縦 | 320×568 | 1.0 / 2.0 | プレイヤー全体表示、overflowなし、レビュー領域あり |
| 旧小型iPhone相当 | 375×667 | 1.0 / 2.0 | 同上 |
| 大型phone縦 | 430×932 | 1.0 / 2.0 | 同上 |
| iPad compact縦 | 320×1024 | 1.0 / 2.0 | 同上 |
| iPad縦 | 768×1024 | 1.0 / 2.0 | 同上 |

Light／Darkの両テーマを既存の全体要件に従って確認する。

### 11.2 横画面と動的リサイズ

横画面専用デザインの新設は今回の対象外とする。ただし、アプリはiPhone／iPadの横画面をサポートしているため、次を非回帰条件とする。

- 横画面でクラッシュまたはoverflowが発生しない
- 動画、5つの再生操作、工程レビュー操作へスクロール等で再到達できる
- 画面回転、Split View、Stage Manager、ウインドウリサイズで再生位置、再生速度、選択タブ、dirty入力を失わない
- 高さが通常縦画面より小さい場合は、到達性を維持するための縮小、プレイヤーの一時的な非表示、または画面全体のスクロールを許容する
- 横画面の例外構成を通常縦画面へ適用しない

## 12. Safe Area

次によって動画プレイヤーまたは操作が隠れないこと。

- ステータスバー
- ノッチ
- Dynamic Island
- Home Indicator
- AppBar
- 非対称な左右Safe Area
- 画面下部の既存UI

画面高さは、実際にWidgetへ与えられた制約と `MediaQuery` のinsetを使用して決める。固定の端末別Safe Area値を実装条件にしない。

---

## 13. キーボード表示時

反省点または症例メモの入力中は、フォーカスされた入力欄、編集中の文字、保存操作へ到達できることを優先する。

- `viewInsets.bottom`を考慮する
- 選択中の工程レビュー内容を縦スクロールできる
- 必要に応じてフォーカス中の入力欄を自動的に表示範囲へ移動する
- キーボード表示中は、動画の縮小、動画だけの非表示、または動画プレイヤー領域全体の一時的な非表示を許容する
- キーボード表示によってVideoPlayerControllerを破棄または再生成しない
- キーボードを閉じた後は、通常レイアウトへ確実に戻す
- 復帰後は、動画プレイヤー全体と5つの再生操作を同時表示する
- 復帰によって再生位置、再生／停止状態、再生速度、選択タブ、入力内容、dirty状態を失わない

## 14. 読み込み・警告・エラー状態

### 14.1 動画を利用できない状態

動画未登録、実体なし、不正参照、確認失敗、再生失敗では、5つの再生操作を表示しないことを許容する。代わりに、既存要件に従い、状態、データが保持されていること、次に行える回復操作を表示する。

### 14.2 利用可能な動画を維持した警告

利用可能なVideoPlayerControllerを維持したまま、データ更新失敗等の警告を表示する場合は、警告によって動画プレイヤーの操作ボタンを画面外へ押し出してはならない。

次のいずれかで対応する。

- 警告を工程レビュー側のスクロール領域へ配置する
- 動画の高さを縮小して、警告とプレイヤー全体を表示する
- 操作を隠さないコンパクトな警告表示にする

通知を動画へ重ねて術野や操作を隠してはならない。

### 14.3 症例削除済み・保存競合

既存のデータ保護と回復操作を優先する。通知内容を表示するために通常プレイヤー構成を変更する場合でも、overflow、到達不能操作、ドラフト消失を発生させない。

---

## 15. 変更してはいけないもの

今回の修正では、次を変更しない。

- 症例データモデル
- 工程データモデル
- DBスキーマ、保存形式、既存症例との互換性
- 動画ファイルの保存・選択・移行方法
- 工程開始・終了時刻の保存契約
- 評価、反省点、症例メモの保存契約
- 各工程の定義と表示順
- 症例一覧、症例詳細、分析画面
- 5秒・15秒のスキップ量と境界制御
- 動画位置通知の局所更新設計

レイアウト修正に直接関係しないリファクタリングは行わない。

---

## 16. 今回の対象外

- 動画の全画面表示
- 横画面専用UIの新設
- ピンチ操作による動画拡大
- 新しい再生速度機能
- 新しい動画編集機能
- 再生操作の全面的なデザイン変更
- 工程レビュー画面全体のデザイン刷新
- DB変更
- 新しい工程の追加

対象外であることは、既存機能や既存対応環境を壊してよいことを意味しない。

## 17. 受け入れ条件

### 17.1 前提

以下の「通常状態」の項目は、利用可能な動画の初期化完了後、キーボード非表示の縦画面で判定する。

### 17.2 通常状態の画面表示

- [ ] 動画全体、時刻・速度、シークバー、5つの再生操作が同時に完全表示される
- [ ] 動画プレイヤー領域の操作に縦スクロールが不要である
- [ ] 動画プレイヤー領域自身が縦スクロールしない
- [ ] 動画と5つの再生操作の間に工程レビューUIや通知バナーが入らない
- [ ] 5つの再生操作が1行で正しい順序に並ぶ
- [ ] 5つの再生操作が画面端やSafe Areaで切れない
- [ ] 時刻・速度行とシークバーが画面端で切れない
- [ ] 動画のアスペクト比が維持される
- [ ] 動画の全体が表示され、クロップされない
- [ ] 工程TabBar全体が表示される
- [ ] 工程レビュー内容の表示領域が96 logical pixels以上ある
- [ ] RenderFlex overflowを含むレイアウト例外が発生しない

### 17.3 スクロール

- [ ] 選択中タブの工程レビュー内容だけを縦スクロールできる
- [ ] 工程レビュー内容を先頭から末尾までスクロールしても、動画プレイヤーの矩形が変化しない
- [ ] 開始、終了、再設定、自己評価、反省点、症例メモへ到達できる
- [ ] 工程レビュー操作をタップする時点で、通常状態の動画と5つの再生操作が画面内に残る
- [ ] TabBarの横スクロールを維持する

### 17.4 再生操作

- [ ] 動画を見ながら15秒戻る操作ができる
- [ ] 動画を見ながら5秒戻る操作ができる

## 18. テスト要件

### 18.1 Widgetテスト

今回の不具合は「Widgetが存在するが画面外にある」ため、存在確認だけを合格条件にしてはならない。

動画プラグインへ依存せずレイアウトを検証できるよう、必要最小限の範囲で動画プレイヤー領域またはレイアウト本体を独立Widgetにすることを許可する。

少なくとも次を自動確認する。

1. §11-1のviewportと文字倍率
2. 16:9、4:3、9:16の動画比率
3. 5つの操作の存在、順序、同一行配置
4. 各操作、動画、時刻・速度、シークバーの矩形が画面本体内に完全に含まれること
5. 各タップ領域が44×44以上であること
6. 隣接するSemantics領域が重ならないこと
7. 工程レビューをスクロールする前後でプレイヤーの矩形が同一であること
8. 工程レビュー内容の表示領域が96px以上であること
9. `tester.takeException()` がnullであること
10. テスト中に捕捉したFlutterレイアウト例外とoverflow報告がないこと
11. キーボード表示・非表示後のレイアウト復帰と状態維持
12. 動画未登録、確認中、エラー、警告状態のoverflowなしと回復操作への到達

既存構造上ほかの実装が適切な場合は変更してよいが、最終動作とテストが本要件を満たすこと。
